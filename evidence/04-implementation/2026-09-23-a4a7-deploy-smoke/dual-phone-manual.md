## 1. 验收顺序（11 步，每步截图+记录时间）

1. **A7**：A 端家庭 Tab 正常开放（真实家庭页，非占位）→ 截图 A7-T01。
2. A 端生成邀请（可携带测试提醒电话：填号码→必须勾选授权说明→生成）→ 截图 A6-P02；记录邀请码仅掩码（KXJ…后2位）。
3. B 查看邀请并加入家庭（无码态/错码态可顺带核验文案）→ 加入成功。
4. A 确认成员关系（家庭页出现"已授权"成员卡）→ 截图 A7-T04。
5. **A3**：B 家属视角查看首页/趋势/记录列表+详情/用药列表+历史——数据为 A 的授权范围数据；详情无删除入口；用药列表无计划编辑入口 → 截图 A3-F01..F04。
6. **A4**：B 代录血压 128/78、代录血糖 6.4、用药"已服"或"跳过"→ 截图 A4-F01..F03；B 确认无计划增删改/记录删除入口 → A4-F04。
7. **A 端归属核对（接口/数据库佐证，截图不单独作证）**：A 首页/记录列表可见代录记录；用 tcb 只读查询 health_records 该两条：`_openid=A 掩码`、`ownerOpenId=A`、`createdByMemberOpenId=B 掩码`、`createdByRole='member'`、`source='family'`；medication_confirmations 代确认文档同审计字段。查询输出脱敏后归档。
8. **A6**：B 家属首页电话提醒入口（脱敏号 138****xxxx）→ 点击 → **只到系统拨号确认界面，不实际拨出**（取消）→ 截图 A6-P03/P04；A 清空电话 → B 刷新见"未配置"态 → A6-P07；A 重设电话并关闭 B 的 remind → B 刷新无电话入口 → A6-P05；A 恢复 remind。
9. **A5**：A 修改权限（关 bloodGlucose read）→ B 刷新：血糖数据消失/相应页面 scopeDenied；再 A 撤销 B → 记录撤销时间。
10. **B 端撤销后行为**：B 停留页返回/重开各家属页 → 全部拒绝态或空态；旧数据不回填；代录入口消失；此时 B 尝试代录（若入口残留经 URL 直达）→ 服务端拒绝 → 截图 A4-F05 + A3-F05；B 端 phone 取号 → 拒绝（A6-P08）。
11. **清理**：按 openId 掩码、memberId、source='family'、精确 _id 删除本轮 records/confirmations；family_members 关系行按验收决定保留（revoked 态）或恢复 active 供复验；attempts 文档如有新增走 TTL。清理命令与 n 值记录归档。

## 2. 证据纪律

- 截图保存：`evidence/04-implementation/visual-input/screenshots/`，文件名 = 清单编号（如 `A4-F01-20260923-1130.png`）；每张附操作步骤与真实时间（同目录 shots-log.md 追加一行：编号/时间/设备/操作/预期/实际）。
- 不摆拍、不手工伪造页面状态；失败即如实截图记录。
- 截图只证明页面显示；服务端鉴权/归属/频控/写入以**接口响应或数据库记录**单独佐证（步骤 7 及每步"配对佐证"列）。
- 电话提醒只到系统拨号确认界面，不实际拨出。
- 不输出：密钥、完整 openid、完整手机号、邀请码明文、真实健康数据。
- A2-S01 / A2-S06 不补拍（用户已明确不提供）。

## 3. 判定口径
